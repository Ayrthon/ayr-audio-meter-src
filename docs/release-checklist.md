# Release checklist

The in-app updater (see `src/updater.rs`) polls
`https://api.github.com/repos/Ayrthon/ayr-audio-meter/releases/latest` on every
startup. That's the **public downloads repo** — this source repo
(`Ayrthon/audio-meter`) is private, and the GitHub Releases API returns 404 on
private repos to unauthenticated clients, so we have to publish releases to a
sidecar public repo.

```
Ayrthon/audio-meter           ← PRIVATE, source code lives here
Ayrthon/ayr-audio-meter       ← PUBLIC, installers + release notes only
```

If you ever need to move the release feed, change the `UPDATE_REPO` constant
in `src/updater.rs`, bump + rebuild, and publish to the new repo. Until both
sides match, installed clients will not see new releases.

## One-time prerequisites

- Windows toolchain installed (rustup + MSVC build tools) — see the top of
  `launch-release.sh` for the exact winget commands.
- Inno Setup 6 installed (`installer\build-installer.ps1` looks for
  `ISCC.exe` under `%LOCALAPPDATA%\Programs\Inno Setup 6\` or Program Files).
- `gh` CLI authenticated (`gh auth login`). The same account needs write
  access to both `audio-meter` (source pushes) and `ayr-audio-meter`
  (release publishes).

## Every release

1. **Bump the version** in **two** places (keep them in lockstep — the updater
   compares `Cargo.toml`'s `CARGO_PKG_VERSION` against GitHub's `tag_name`,
   and the installer filename comes from the `.iss` `#define MyAppVersion`):

   - `Cargo.toml` → `version = "2.0.0"`
   - `installer/audio-meter.iss` → `#define MyAppVersion "2.0.0"`

   (Substitute the current version number for subsequent releases — the
   examples below all use `2.0.0` but the pattern is the same.)

2. **Commit + push** the bump on the private source repo's default branch:

   ```powershell
   git commit -am "release: 2.0.0"
   git push
   ```

3. **Build the installer** from repo root (spends ~90 s on
   `cargo build --release` then ~5 s compiling the `.iss`). The output lands
   at `dist\AYR-Audio-Meter-Setup-2.0.0.exe`:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\installer\build-installer.ps1
   ```

4. **Create + publish the GitHub Release on the public sidecar repo**,
   attaching the installer. The tag **must** start with `v` so the updater's
   `is_newer` comparator strips it cleanly. `--repo` is mandatory because
   we're running `gh` from inside a checkout of the *source* repo but
   publishing to a different repo.

   Write release notes to a temp file using the template below (this way the
   note about the auto-generated `Source code` links — which GitHub refuses
   to let us hide from the page — shows up on every release and primes the
   user to click the correct `.exe`):

   ```md
   ### Install

   Download **`AYR-Audio-Meter-Setup-2.0.0.exe`** from the Assets below and run it.

   > ℹ️ The `Source code (zip)` and `Source code (tar.gz)` links are auto-generated by GitHub and contain only this repo's README — they're not the app. They can't be hidden (GitHub limitation).

   ### What changed

   Short changelog here. Rendered verbatim in the in-app update modal
   (scrollable), so bullets and links are fine.
   ```

   Then publish:

   ```powershell
   gh release create v2.0.0 `
     .\dist\AYR-Audio-Meter-Setup-2.0.0.exe `
     --repo Ayrthon/ayr-audio-meter `
     --target main `
     --title "2.0.0" `
     --notes-file .\release-notes.md
   ```

   The modal trims whitespace and scrolls long bodies.

5. **Smoke-test the updater + license flows** on the dev machine:
   - Install a previous version (e.g.
     `dist\AYR-Audio-Meter-Setup-1.6.8.exe`).
   - Launch it. Within a couple seconds after the splash solo phase ends you
     should see the "Update available — 2.0.0" modal. Clicking **Update now**
     should download into `%TEMP%`, close the app, and auto-run the Inno
     Setup wizard. Restart Manager will relaunch the new build when the
     installer finishes.
   - On first launch of the upgraded build, the "Welcome to AYR Audio Meter"
     trial modal should appear exactly once (14 days remaining). The "Trial:
     14 days left" chip should be visible in the top bar next to the update
     chip. The Controls tab's **LICENSE** card mirrors the same status.
   - Exercise the license gate in **release** mode by launching with
     `AYR_AUDIO_METER_LICENSE_OVERRIDE=expired`. The app should open, freeze
     the meters, and pop an un-dismissable **Trial expired** modal with
     key-entry and Buy buttons. `expired` / `invalid` / `trial:3` /
     `licensed` / `offline:5` are the quick branches to check.

## 2.0.0 release specifics

The 2.0.0 release turns on the paid-license gate (see `src/license.rs`).
Steps that only apply to this cutover:

1. **Lemon Squeezy store is live.** Confirm that the `CHECKOUT_URL` constant
   in `src/license.rs` points at the **Live** (not Test-mode) hosted checkout
   URL before cutting the release build. A `grep` for `/checkout/buy/` should
   return exactly one hit, and opening it in a browser should show a live
   Lemon Squeezy checkout (no "Test mode" banner).
2. **Release notes callouts.** The 2.0.0 notes should mention:
   - Trial + paid licensing is live from this build onward; 1.x stays free
     forever.
   - Hardware change / Windows reinstall policy (self-deactivate old via the
     LS customer portal; reactivate on new PC; 2 activations default).
3. **Webhook / Cloudflare Worker is NOT required for 2.0.0.** The app hits
   LS directly from the client. A Worker only becomes useful if we later add
   Ed25519-signed offline grants (see "Non-goals" in
   `plans/lemon_squeezy_licensing_+_trial_*.plan.md`).

## Troubleshooting

- **Updater picks the wrong asset.** It selects the *first* asset whose
  filename ends in `.exe` (case-insensitive). Only attach the installer —
  never upload debug symbols or a secondary `.exe` next to it.
- **Modal never appears.** Check `startup.log` (written next to the app's
  data dir); the updater logs `updater: checking …`, `updater: update
  available: …` / `updater: up to date`, or `updater: check failed: …`. A
  404 there usually means the release is still a **draft** — the API's
  `releases/latest` endpoint only returns published releases. It can also
  mean you accidentally published to `Ayrthon/audio-meter` (private) instead
  of `Ayrthon/ayr-audio-meter` (public).
- **Download fails with a TLS error.** We use `ureq` with `rustls` +
  `webpki-roots`, so the user's OS cert store is not consulted. A corporate
  MITM proxy that rewrites the api.github.com cert will surface as
  `NetworkError(…)`; this is silent in the UI by design.
